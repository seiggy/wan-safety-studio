# Agent instructions

## Aspire (local dev)

- **Do not stop or restart the AppHost** (`aspire stop`/`aspire start`) unless `AppHost.cs` itself changed (resources, parameters, env wiring, packages). If it is already running, leave it running.
- After changing code in one app, restart only that resource: `aspire resource api rebuild` (.NET API, `src\`) or `aspire resource web restart` (Vite UI, `web\`), or the equivalent Aspire MCP `execute_resource_command`. Then `aspire wait <resource>` before testing. The web UI normally hot-reloads, so it rarely needs a restart.
- Check state with `aspire describe`, `aspire logs <resource>` and `aspire otel traces|logs` instead of restarting to "see what happened".
- Start the AppHost only when none is running (`aspire ps`). Always pass `--non-interactive`.
- The backend is the .NET 10 solution in `src\` (Clean layering: `Domain` -> `Application` -> `Infrastructure` -> `Server`; `AppHost` + `ServiceDefaults` for Aspire). Tests: `dotnet test tests\VideoSafetyStudio.Tests`. There is no Python control plane: the Azure ML generation provider and job submission live in the .NET server (`Generation__Provider=azureml`), which is also what the hosted container (`src\VideoSafetyStudio.Server\Dockerfile`) runs. `trainers\` holds the Python trainer containers. The vision dataset builder is gated by `FEATURE_DATASET_BUILDER_ENABLED=true`.
- Restart a changed .NET resource with `aspire resource api restart`; the UI pushes updates over SSE (`/api/events`) instead of polling.
- GPU build-only preparation/model implementation is in `build\gpu\` (see its README); P4 publication entry points are in `scripts\ci\`, and the lifecycle is hosted in the .NET server (Administration UI, `/api/studio/*`) with `scripts\recovery` as the independent emergency path. `scripts\Invoke-WanSafetyStudio.ps1` is a frozen legacy tool that accepts only Status/Stop/Check for an un-migrated v1 deployment (offline test: `pwsh -NoProfile -File scripts\Test-LegacyLifecycle.ps1`); delete both after the v1 to v2 migration is verified. Entra bootstrap is the manual runbook `docs\operations\entra-bootstrap.md`; local settings are a hand-written `appsettings.Development.json`. Model pins moved to `build\gpu\wan-pinned-manifest.json`. Build checks: `python -m unittest discover -s build\gpu -p 'test_*.py' -v`; optional `WAN_STUDIO_P2_UPSTREAM` points to an exact pinned Git source fixture. Never build/pull images or download weights without approval.
- While the AppHost runs, `dotnet test` into the repo cannot overwrite locked server binaries: use `aspire resource api rebuild` to compile, and `dotnet test tests\VideoSafetyStudio.Tests --artifacts-path .artifacts` to test.

## Agent skills

### Regional infrastructure cutover

- `infra\` is the P3 durable-only regional root (`regions`, `control_region`, optional `legacy_region`; no machine contract: outputs are informational only and Terraform sets no studio app setting). It never owns compute/NAT/PIP or customer landing-zone resources. See `infra\README.md` before any real plan/migration.
- Legacy Deploy/Prepare/Portal/Publish/Start and automatic old-address Terraform reconciliation are blocked against this root. Cached v1 Status/Stop remain for emergency pre-migration release; hosted lifecycle/promotion is P4/P5.
- Run Terraform checks in isolated sources without customer tfvars/state: `pwsh -NoProfile -File infra\tests\Export-MockedContracts.ps1`. Migration checks: `python -m unittest discover -s infra -p 'test_*.py' -v`. `infra\migration.py` is read-only and never executes its proposed state commands.
- P5 hosted lifecycle (`src\VideoSafetyStudio.*\Operations`, `StudioAdminEndpoints`) is documented in `docs\operations\hosted-lifecycle.md`. Configuration is .NET options: the `Studio` section (`StudioOptions`, evaluated at start by `ConfigHealth`; the host never stops for bad configuration: it serves the anonymous `/health-ui` page and `GET /api/health/config`, runs no workers and answers `/api` and `/auth` with 503 until the settings are fixed and the app restarted) is supplied as environment variables / App Service application settings (`Studio__Regions__<region>__...`); there is no receipt, `Studio__Foundation` or `Studio__Selection`. Hosted multi-region operation is on exactly when `Studio:Regions` has entries; then the host keeps the durable fence in `wan-control` and `AzureMl__Armed` is irrelevant. Live limits (concurrency, timeouts, priority, queue wait) are edited in the Administration page and bounded by the `Studio` ceilings. The authoritative guide is `docs\configuration.md` (App Service first), the runbook is `docs\operations\app-service-settings.md`, and the example is `docs\samples\studio-settings.json.example` (same shape as `contracts\fixtures\studio-settings.json`). Checks: `dotnet test tests\VideoSafetyStudio.Tests --filter FullyQualifiedName~StudioLifecycleTests`. P6 routing (`RegionalRouting.cs`, `RegionalAzureMlBackend.cs`; `RegionalRoutingTests`) and P7 administration (settings in `StudioLifecycle.Settings.cs`, `web\src\features\admin`; `StudioSettingsTests`, `AuthTests` role matrix, `npm test` in `web`) are in the same document: `operations/settings.json` holds the live limits and each role is its own session claim. P8 remote training (`AzureMlTrainingCompute`, `TrainerBindings`, `scripts\ci\publish_trainer.py`, `contracts\trainer.schema.json`; `RemoteTrainingTests`, `test_pipeline.py`) is documented in `docs\vision-trainers.md`; the hosted dataset builder flag stays off. Offline verification results and the live acceptance plan are in `docs\operations\verification-handoff.md`; `scripts\ci\check_server_content.py` checks a publish folder or image `/app`. Never invoke lifecycle routes against real Azure without explicit authorization.
- P4 private workflows and their environment/identity contracts are documented in `docs\operations\private-pipelines.md`. Never dispatch them without explicit authorization. They read one explicit settings document (`STUDIO_SETTINGS_JSON`/`STUDIO_SETTINGS_PATH`: the same `Studio` section plus a `Pipeline` section the web host never reads), Terraform inputs from `STUDIO_TFVARS_*` and the backend from `STUDIO_BACKEND_*`; `Stop-Studio.ps1` takes `-SettingsPath`. Ordinary PR CI must stay unprivileged and off private runners. Pipeline checks: `python -m unittest discover -s scripts\ci -p test_pipeline.py -v`; build `tools\VideoSafetyStudio.Contracts` and set `STUDIO_CONTRACT_TOOL` for actual cross-language cases. Recovery checks: `pwsh -NoProfile -File scripts\recovery\Test-StudioRecovery.ps1`.
