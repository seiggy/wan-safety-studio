## Protected entry points

| Workflow | Environment | Purpose |
| --- | --- | --- |
| `release.yml` | `studio-build` | Build one selected server, GPU or trainer artifact |
| `promote.yml` | `studio-publish` | Promote a sealed GPU artifact (`component: gpu`) or trainer image (`component: yolox`) to the configured regions |
| `foundation.yml` | `studio-plan`, then `studio-apply` | Separately review and apply the exact private saved binary plan |
| `deploy-server.yml` | `studio-server` | Deploy a verified server catalog ID by immutable registry digest |
| `recover.yml` | `studio-recovery` | Invoke independent native emergency release |

They accept only protected default-branch manual dispatches on ephemeral Linux
x64 private runners labelled `wan-private`. Configure required reviewers and
runner-group restrictions before use. Ordinary PR CI has no Azure credentials
and must never use that runner group.

The runner needs existing private DNS/routing to Blob/File, ACR, AML, Vault and
the site's private endpoints. Public GitHub runners do not supply that connection.
Approved ARM/Entra/GitHub/feed/source outbound connectivity is also required.

## Configuration and identity

Keep the settings document (the `Studio` section the site uses, plus a `Pipeline` section the web host never reads) in masked protected environment secrets, outside Git. Release, promote, deploy-server and recover read it from
`STUDIO_SETTINGS_JSON` or `STUDIO_SETTINGS_PATH`. `foundation.yml` also reads the Terraform customer input from
`STUDIO_TFVARS_JSON` or `STUDIO_TFVARS_PATH`, and the state backend from `STUDIO_BACKEND_JSON` or `STUDIO_BACKEND_PATH`.
No pipeline reads a Terraform output or a receipt. See [Configuration](../configuration.mdx#settings-read-by-pipelines). Each environment uses its own
approved federated Azure CLI identity; no workflow creates credentials or grants
tenant consent. Terraform uses that isolated short-lived CLI session.

The full variable, permission, private backend/artifact-container and approval
contracts are in the repository's `docs\operations\private-pipelines.md`. Complete
the verified-OFF migration in `infra\README.md` before applying this root to old
state. The routine pipeline rejects every delete/replacement, including changes
that need the separate migration runbook.

## Pipeline settings

The `Pipeline` section of the settings document is read only by the pipelines. None of its values is an App Service setting.

| Setting | What it is | Required by | How to find it |
| --- | --- | --- | --- |
| `Pipeline:PublisherPrincipalId` | Object ID (GUID) of the identity the release and trainer publishing workflows sign in as. Publication checks that the authenticated Azure CLI caller is exactly this principal. | Release and trainer publishing | Azure portal, Microsoft Entra ID, the enterprise application or managed identity, Object ID; or `az ad sp show --id <client id> --query id -o tsv`. |
| `Pipeline:SiteId` | ARM ID of the one shared App Service the server deployment may change. | `deploy-server.yml`, `recover.yml` | Azure portal, the web app, Overview, JSON View, Resource ID; or `az webapp show -g <rg> -n <site> --query id -o tsv`. |
| `Pipeline:Regions:<region>:WorkspaceIdentityId` | ARM ID of the user-assigned identity the Azure ML workspace uses. Before publishing, the publishing step verifies the workspace is wired to this identity. A missing value stops publication. | Release publishing to the region, trainer publishing | Azure portal, the identity, Properties, Resource ID; or `az identity show -g <rg> -n <identity> --query id -o tsv`. |
| `Pipeline:Regions:<region>:KeyVaultId` | ARM ID of the key vault the Azure ML workspace uses. The same step verifies the workspace is wired to this vault. A missing value stops publication. | Release publishing to the region, trainer publishing | Azure portal, the key vault, Properties, Resource ID; or `az keyvault show -g <rg> -n <vault> --query id -o tsv`. |

`<region>` is the same key used under `Studio:Regions`.

## Immutable promotion

GPU builds stage an explicitly unready private registry image, obtain its real
manifest digest, then run the isolated P2 CPU probe. A probe failure publishes no
sealed build or ready binding. Model caches and licence cards must already exist
on the runner; GPU builds do not download missing weights. Trainer-image weight
acquisition has a separate explicit protected-environment approval.

Promotion verifies every blob's bytes, exact completed AML registrations and the
same image digest in the destination registry. Model snapshot names remain stable
when only code or the image changes; model versions are positive integers.
Bindings are create-only and written last, so a partial region stays unavailable.
Server deployment consumes its approved catalog ID, never rebuilds and never
arms submission.

## Independent recovery

Quiesce other deployment/operational writers first. P4 has not yet implemented
P5's durable operation fence. Recovery does not wait behind a stuck build or plan.

```powershell
pwsh -NoProfile -File scripts\recovery\Stop-Studio.ps1 `
  -SettingsPath <outside-git-settings.json>
```

Use normal explicit Azure CLI login/scope. Recovery does not depend on Python,
the server/.NET SDK, Terraform, Docker, pricing or fresh Terraform output. It
stops/verifies the shared host, attempts every region, deletes only exact owned
compute, proves job termination, then releases only owned egress. Foreign
networking, ambiguous responses or incomplete release return failure, not a
prepared-looking success. The host remains stopped.

Local checks and all known unverified limits are listed in
`docs\operations\private-pipelines.md`; none constitutes live Azure evidence.
