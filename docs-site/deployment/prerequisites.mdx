## Landing-zone inputs

Only Azure public cloud, one subscription and one region are supported. All supplied resources must be in `subscription_id`, and the subnets must be in `location`.

| Input | Variable | Notes |
| --- | --- | --- |
| Dedicated GPU subnet | `gpu_subnet_id`, `gpu_subnet_cidr`, `gpu_subnet_dedicated` | Only this studio may use it. `defaultOutboundAccess=false`, no delegation, no unrelated NAT. You must set `gpu_subnet_dedicated` to `true` explicitly. |
| Private endpoint subnet | `private_endpoint_subnet_id` | Distinct from the GPU subnet. |
| Six private DNS zones | `private_dns_zone_ids` | blob, file, vault, registry, api and notebooks, linked and resolvable from the operator, GPU and creator networks. |
| Log Analytics workspace | `log_analytics_workspace_id` | Application Insights is created against it. |
| GPU NSG (optional) | `existing_gpu_nsg_id` | Required when policy already attaches an NSG to the GPU subnet. |
| App Service subnet and zone (optional) | `portal.subnet_id`, `portal.dns_zone_id` | Empty subnet delegated to `Microsoft.Web/serverFarms`, and `privatelink.azurewebsites.net`. |
| GPU egress | Routed egress, or `manage_compute_egress` | With `defaultOutboundAccess=false` the GPU nodes need a path to Azure service endpoints. |
| Client DNS | None (customer side) | Creators and the operator must resolve the site hostname to the private endpoint. See [Networking](./architecture/networking.mdx). |

The network owner supplies these. The studio never creates or changes subnets, NSG rules on a customer NSG, route tables, DNS zones, DNS links or client DNS.

## Tools on the operator workstation

| Tool | Version | Needed for |
| --- | --- | --- |
| PowerShell | 7.4 or later | Every script (`#requires -Version 7.4`) |
| Azure CLI | Current | Login, ACR login, token acquisition |
| Terraform | 1.9 or later, below 2.0 | Deploy and state reconciliation. The lock pins AzureRM 5.6.0 and AzAPI 2.12.0. |
| Git | Any | Source checkout |
| Python and uv | Python 3.12 | Prepare, through a locked uv environment |
| Docker | Linux containers | Prepare (builds the GPU image) and Publish (builds the server image) |
| .NET 10 SDK and Node.js | Current | Only the local `Portal` action |

Prepare needs substantial local disk. The eight pinned model files alone are about 41.6 GiB. Some of the models may require license acceptance or access approval from the model owner before the download works.

Local validation of the scripts was done on Windows only. Linux and macOS use the same code paths, but process identity checks and the end-to-end run are unverified there.

## Resource providers

Automatic registration is turned off on purpose. These providers must already be registered in the subscription:

`Microsoft.Network`, `Microsoft.ManagedIdentity`, `Microsoft.Storage`, `Microsoft.KeyVault`, `Microsoft.ContainerRegistry`, `Microsoft.Insights`, `Microsoft.MachineLearningServices`.

The Log Analytics workspace's subscription also needs `Microsoft.OperationalInsights`, and the portal needs `Microsoft.Web`.

## Quotas

| Quota | Requirement | How to check |
| --- | --- | --- |
| Azure ML `TotalLowPriorityCores` | 24 free cores | [Compute and cost](./architecture/compute-and-cost.mdx#quota-and-capacity) |
| Azure ML `standardNCADSA100v4Family` low priority | 24 free cores, or `-1` for a shared pool | Same |
| App Service plan SKU in the region | 1 VM of the SKU you choose, when `portal` is set | The usages API does not show the per-SKU limit. The definitive test is to create and delete an empty B1 Linux plan. |

Quota does not guarantee Spot capacity at run time. Check the A100 SKU is unrestricted in your region with `az vm list-skus`, as shown on the same page.

A zero-quota App Service SKU fails Deploy with `Current Limit (<sku> VMs): 0`. Nothing is deleted, and a rerun after the quota is granted continues from where it stopped.

## Permissions

| Who | Needs |
| --- | --- |
| Deploying identity | Enough rights to create the owned resources and their role assignments, to join the supplied subnets, and to associate private endpoints with the supplied DNS zones. Role assignment writes are not part of Contributor, so confirm this with the subscription owner. |
| Operator (`operator_principal_id`) | Receives scoped data roles from Terraform. Needs the Azure CLI signed in as that same user. |
| Identity owner or the operator | Directory rights to create applications, security groups and role assignments, for `Initialize-PortalAuth.ps1`. An Entra administrator must grant tenant-wide consent once. |
| Network owner | Can edit the supplied subnets, zones, links and NSG. |

`operator_principal_id` is the Entra object ID, not the application or client ID. Look it up with `az ad signed-in-user show --query id --output tsv` while signed in as the operator.

## The operator Azure profile

The scripts use your Azure CLI session and accept no alternate credentials.

```powershell
az login --tenant <tenant-id>
az account set --subscription <subscription-id>
```

If the signed-in tenant or subscription differs from the configured one, the script stops with "Wrong Azure CLI context". Terraform and Python child processes run with a sanitized environment. They cannot inherit `ARM_CLIENT_*` secrets, managed-identity or OIDC switches, or `TF_VAR_*` overrides.

If you keep one Azure CLI profile per customer, activate the right one before each run, in the same shell. A default resource group set in that profile can break `az acr` commands. The scripts pass `--resource-group` explicitly for that reason. But your own `az acr` commands need it too. `AZURE_CONFIG_DIR` is passed through to the child processes, so a per-customer config directory works.

The scripts also keep an operator cache outside the repository: `%LOCALAPPDATA%\wan-safety-studio\<subscription>-<deployment_name>` on Windows. It holds the Terraform output receipt (`foundation.json`), prepared-asset manifests and local arming state. Override it with `-CacheDirectory` or the `WAN_STUDIO_CACHE` environment variable, and use the same value for every command. Restrict access to it and never copy it between deployments.

## Private network access for the operator

Deploy itself only talks to ARM. Prepare, Publish, Initialize-PortalAuth and Start also reach private endpoints (blob, vault, registry, workspace), so the workstation needs private DNS resolution and a network path, usually through the VPN. The scripts fail early with a clear message if a hostname resolves outside private address space.

## Package feeds in an enterprise environment

Several steps download packages, and an enterprise that blocks public registries has to point each ecosystem at one approved feed. The repository does not include your feed. Check these places:

| Ecosystem | Where it is configured | What to do |
| --- | --- | --- |
| NuGet | Repo-root `nuget.config` | The file clears all sources and lists one. Replace the single source with your feed. The Docker build copies this file. |
| npm | `web\.npmrc` | Set `registry=` to your feed. |
| PyPI | The `WAN_STUDIO_PYPI_INDEX` environment variable | Set it to your HTTPS PyPI index for Prepare and Publish. It must have no embedded credentials, query or fragment. |

`WAN_STUDIO_PYPI_INDEX` also feeds the release version hash, so changing the index produces a new Prepare. The scripts also pass `UV_NATIVE_TLS`, `UV_HTTP_TIMEOUT` and `UV_HTTP_RETRIES` through to uv, which helps on a corporate TLS chain and a slow first fetch from a mirror.

```powershell
$env:WAN_STUDIO_PYPI_INDEX = 'https://<your-feed>/pypi/simple'
$env:UV_HTTP_TIMEOUT = '600'
$env:UV_HTTP_RETRIES = '5'
```

The Dockerfile accepts BuildKit secrets (`npmrc` and `nugetconfig`) so credentials never land in an image layer, but Publish does not pass any (see [Update and redeploy](./guides/update-and-redeploy.mdx#builds-behind-an-authenticated-feed)). Keep credentials in user-level configuration only. Newly published package versions are often quarantined for a few days by enterprise feeds, so if a just-released version does not resolve, pin an older one.

One more place names a feed. The Copilot CLI that powers the video helper is downloaded by the SDK during the server build, from the npm registry set in `CopilotNpmRegistryUrl` in `src\VideoSafetyStudio.Infrastructure\VideoSafetyStudio.Infrastructure.csproj`. Point that at your feed too. (`docs\app-service.md` describes this download as coming from GitHub releases. The csproj is the source of truth.)
