## P3 cutover boundary

The root now manages durable regional foundations, not compute/NAT/PIP. The protected
[private pipelines](./guides/private-pipelines.mdx) (`foundation.yml`, `release.yml`, `promote.yml`,
`deploy-server.yml`) deploy and promote, and the hosted lifecycle in the .NET server starts and stops compute. The
old `Invoke-WanSafetyStudio.ps1` Deploy, Prepare, Portal, Publish and Start actions no longer exist. That script is now a
frozen legacy tool that accepts only `-Action Status`, `-Action Stop` and `-Action Check`, for the emergency release of a
pre-migration deployment. Do not apply this root over existing state without the reviewed verified-OFF address migration
in `infra\README.md`.

The real customer config/state files have not been edited or migrated. Keep the
old config and the preserved legacy v1 receipt available outside Git for legacy emergency release, and the old Terraform
state until the migration is verified.
Use a separate explicit new regional JSON file; do not let old automatic tfvars
silently supply omitted values. In a pipeline, the same JSON comes from the protected `STUDIO_TFVARS_JSON` secret or an
approved runner path (`STUDIO_TFVARS_PATH`). The state backend is `STUDIO_BACKEND_JSON` or `STUDIO_BACKEND_PATH`. These are
the Terraform input only. The site's own configuration is separate: see [Configuration](./configuration.mdx).

## Global inputs

| Input | Purpose |
| --- | --- |
| `deployment_name` | Stable 3-16 character lowercase DNS-safe slug |
| `subscription_id`, `tenant_id` | Explicit canonical lowercase nonempty UUIDs; initial support is one subscription/tenant |
| `operator_principal_id` | Explicit operator object ID, not an application/client ID |
| `publisher_principal_id` | Optional explicit publishing identity; null grants no new release publication access |
| `control_region` | A configured region key for one shared host and primary control storage |
| `legacy_region` | Null for greenfield. One existing region for reviewed migration; must remain `control_region` |
| `regions` | Nonempty map keyed by canonical Azure region; one independent workspace/service foundation per entry |
| `portal` | Optional shared host: supplied `subnet_id`, `dns_zone_id`, and `sku` (default B1) |
| `agent`, `key_vault_uri`, `key_vault_id` | Existing helper/vault integration; use secret references, never plaintext credentials |
| `feature_dataset_builder_enabled` | False until remote training/media readiness in P8 |

Existing resources use the exact old `<subscription>:<deployment>` naming hash only
in `legacy_region`. New regional names hash `<subscription>:<deployment>:<region>`.
No region names are hardcoded into infrastructure logic.

## Each regional entry

| Field | Requirement / default |
| --- | --- |
| `gpu_subnet_id` | Supplied dedicated same-subscription GPU subnet |
| `gpu_subnet_cidr` | Its exact canonical IPv4 CIDR |
| `gpu_subnet_dedicated` | Must explicitly be true |
| `private_endpoint_subnet_id` | Supplied separate PE subnet; no configured GPU subnet may serve this purpose |
| `existing_gpu_nsg_id` | Null for an owned NSG, or the exact already-attached customer NSG |
| `private_dns_zone_ids` | Six supplied zones: blob, file, vault, registry, api, notebooks |
| `log_analytics_workspace_id` | Supplied customer workspace; Terraform does not own logging |
| `max_nodes` | Positive whole runtime ceiling, default 1 |
| `max_job_minutes` | Whole runtime job limit 1-120, default 120 |
| `max_payg_hourly_usd` | Finite positive retail admission threshold, default 4; not a billing cap |
| `manage_compute_egress` | Default false; explicit conditional NAT/PIP/dedicated-subnet write policy, not provisioning |
| `egress_public_ip_tags` | Customer-required public-IP policy tags, default empty |
| `compute_enabled` | False only; true is rejected rather than creating compute |

GPU subnets must have default outbound explicitly disabled, no service delegation
and no unrelated NSG/NAT. Both GPU/PE VNets must match that entry's region.
Customer-owned NSGs/rules/associations, VNets, DNS zones/links and logging are never
adopted. Customers supply private routing/DNS between the one host, regional services
and private CI/CD runners.

The six public-cloud zone names remain:
`privatelink.blob.core.windows.net`, `privatelink.file.core.windows.net`,
`privatelink.vaultcore.azure.net`, `privatelink.azurecr.io`,
`privatelink.api.azureml.ms` and `privatelink.notebooks.azure.net`.

The shared host subnet must already be delegated to `Microsoft.Web/serverFarms`
in `control_region`, distinct from every GPU/PE subnet. Its supplied zone is
`privatelink.azurewebsites.net`. Supported private-endpoint SKUs remain B1/B2/B3,
S1/S2/S3, P0v3/P1v3/P2v3.

## Outputs and checks

Terraform creates infrastructure and nothing the app reads. It emits no `studio` output or other receipt, and sets no
studio application settings. You copy the resource IDs it creates into the site's `Studio__*` settings (see
[Configuration](./configuration.mdx#configure-the-site)); the names Terraform derives are not an input to the app.
`gpu_nsg_rules` is a region-keyed security-team handoff, and `portal` is a separate shared-host output.

The GPU has run-container writes/release reads, not account-wide blob access to the
new control container. That grant narrowing is an intentional reviewed role replacement,
not an unintended workspace/service replacement.

Run isolated mocks without customer configuration/state:

```powershell
pwsh -NoProfile -File infra\tests\Export-MockedContracts.ps1
python -m unittest discover -s infra -p 'test_*.py' -v
dotnet test tests\VideoSafetyStudio.Tests --artifacts-path .artifacts --no-restore
```

The exporter copies source/locks/modules/tests to a private temporary directory,
uses native mocked providers and checks the one- and two-region plans. The .NET
tests separately validate the `Studio` settings. No
deployment, state changes, Azure login or GPU spend is needed.
