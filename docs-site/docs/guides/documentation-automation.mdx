# Documentation automation

:::note Historical
Docs used to be updated at commit time by a git hook that started a Copilot agent through `scripts\Update-Docs.ps1`, and `scripts\Install-GitHooks.ps1` turned the hook on. Both scripts were deleted in the P9 cleanup. Authoring is manual now. `.githooks\pre-commit` and `.github\agents\docs-maintainer.agent.md` still exist in the repo, but nothing in the repo installs or runs them for you.
:::

## Update the docs with your change

1. Find the pages for the code you changed in `docs-site/docs-map.json`.
2. Edit those pages in the same pull request, and re-check every snippet you touch against the real file.
3. Run the checks below before you push.

## The docs map

`docs-site/docs-map.json` lists which source paths each page describes. If you add a new area, add its entry in the same change. If you delete a path, remove its entry. Keep an entry only for a path that exists.

## Check before you push

```powershell
cd docs-site
npm run build
node scripts/check-prose.mjs
```

The build fails on broken links. The prose check flags filler and marketing phrases; fix what it reports.

## CI checks

`.github/workflows/docs.yml` runs on pushes and pull requests, or by manual dispatch. It uses Node.js 24 and the approved CFS npm registry, installs with `npm ci`, builds the site, then runs `node scripts/check-prose.mjs` from `docs-site`. It keeps lockfile URLs unchanged. Runners need access to that feed; the workflow has no public-registry fallback.

The npm audit step is report-only. A successful build on `main`, outside a pull request, uploads the site artifact and deploys it to GitHub Pages.
