The Python suites (`test_controls.py`, `test_sdk_controls.py`) and `Test-Controls.ps1` were deleted with `azureml\`. Their coverage moved to the suites below. The mutate-one-field and assert-it-throws pattern still applies.

None of these checks touch Azure. They use fakes, fixture settings documents and mocked transports, so they cost nothing and need no login. They say nothing about real Spot capacity, permissions or private routing.

## The suites

| Area | Run with | Needs |
|---|---|---|
| Guard, job spec, lifecycle, regional backend, server | `dotnet test tests\VideoSafetyStudio.Tests --artifacts-path .artifacts` | .NET SDK from `global.json` |
| GPU build boundary | `python -m unittest discover -s build\gpu -p "test_*.py"` | Python 3.12 |
| Infra state mapping | `python -m unittest discover -s infra -p "test_*.py"` | Python |
| Terraform and cross-layer contracts | `pwsh infra\tests\Export-MockedContracts.ps1` | Terraform, PowerShell |
| Pipeline fault injection | `python -m unittest discover -s scripts\ci -p "test_pipeline.py"` | Hash-locked `scripts\ci\requirements.lock` installed, and `STUDIO_CONTRACT_TOOL` set to the built `VideoSafetyStudio.Contracts` tool |
| Build identity | `python scripts\ci\test_build_identity.py` | Python |
| Shared contract fixtures | `pwsh -NoProfile -File scripts\ci\Test-StudioContracts.ps1` | PowerShell, .NET |
| Emergency recovery | `pwsh scripts\recovery\Test-StudioRecovery.ps1` | PowerShell |
| Web UI | `npm test` in `web` | Node.js |

CI runs these from `.github\workflows\ci.yml`. The workflow has `dotnet`, `web`, `python`, `server-image` and `terraform` jobs; the `python` job builds the contract tool and exports `STUDIO_CONTRACT_TOOL` before the pipeline tests. Its `terraform` job runs `Export-MockedContracts.ps1`.

## Guard tests

The guard rules are covered in `tests\VideoSafetyStudio.Tests`. `AzureMlTests.cs` holds the job spec, ARM body, guard rules and backend flow against a fake workspace. Rules are table-driven: mutate one field of a valid spec and assert the guard throws.

```csharp title="tests/VideoSafetyStudio.Tests/AzureMlTests.cs"
[Theory]
[InlineData(0)]
[InlineData(-5)]
[InlineData(7201)]
public void Guard_rejects_timeouts_outside_one_to_7200(int seconds) => Rejected(s => s with { TimeoutSeconds = seconds });
```

A new rule needs two tests: one that proves the valid case passes, so the rule is not just rejecting everything, and one per way it should fail. See the [backend testing guide](../guides/testing.mdx) for the patterns and fakes.

## Legacy script check

`scripts\Test-LegacyLifecycle.ps1` is the offline test for the frozen `scripts\Invoke-WanSafetyStudio.ps1`. Both will be deleted after the v1 to v2 migration is verified. CI does not run it. Use it only if you change the legacy script, which you should not.

## When you change a safety rule

1. Run `dotnet test tests\VideoSafetyStudio.Tests --artifacts-path .artifacts`.
2. If you touched `build\gpu`, `infra` or `scripts\ci`, run the matching Python suite and, for Terraform or the settings contract, `infra\tests\Export-MockedContracts.ps1`.
3. If you touched recovery scripts, run `scripts\recovery\Test-StudioRecovery.ps1`.
4. If you changed a contract schema or the settings fixture (`contracts\fixtures\studio-settings.json`), run the shared contract fixtures check.

These suites run offline on purpose. The first real generation after a change in a live region is still your smoke test.
