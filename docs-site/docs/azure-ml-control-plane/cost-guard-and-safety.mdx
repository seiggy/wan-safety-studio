The cost model is simple to state. One node, Spot, minimum zero, maximum one, and every job has a server-side timeout. Everything in this page exists to make those facts hard to break by accident, in the operator script, in the Python job path and in the live Azure resources.

## What armed means

"Armed" is a file. `Start` writes `armed.json` into the [operator cache](./overview.mdx#the-operator-cache) as the last step before it starts the local server, and `Stop` deletes it first. It holds three values:

```powershell title="scripts/Invoke-WanSafetyStudio.ps1"
$pendingGate = Join-Path $Cache 'armed.pending'
$gate = [ordered]@{compute=$Foundation.computeName; profile=$Profile; version=$manifest.version}
$gate | ConvertTo-Json | Set-Content $pendingGate
Move-Item -LiteralPath $pendingGate -Destination (Join-Path $Cache 'armed.json') -Force
```

The file is written under a temporary name and renamed, so no reader ever sees a half-written gate. These are the semantics that follow from the code:

- **Armed is a promise from the operator.** It says that this compute, this profile and this prepared release version may take jobs, and nothing about running nodes. An armed studio with zero nodes costs nothing for compute.
- **It names a release.** `job_controls` compares the gate's compute, profile and version with the foundation receipt and the prepared contract. If you re-run Prepare and the version changes, the old gate no longer matches and submissions fail with "Start must arm this prepared profile".
- **Starting the local server does not arm.** The `Portal` action runs the studio with no compute changes. `AzureMl__Armed` is set from whether `armed.json` exists, so the UI shows `armed: false` and generation stays disabled until Start.
- **Hosted sites follow the same switch.** `Set-HostedGate` writes the `AzureMl__Armed` app setting to `true` or `false` on the App Service. Disarm always writes an explicit `false`. Removing the setting would be ambiguous. An app-setting change restarts the site, which is the intent.
- **Stop disarms before it does anything else.** The first writes in `Stop-Demo` are `release-required.json` (a marker that release must finish) and removal of `armed.json`. Submission is off before the slow cloud work starts.

The UI exposes this as `armed` and `generationEnabled` in `GET /api/status`, and `features\environment\messages.ts` turns the combination into text. See [Web UI overview](../web-ui/overview.mdx).

## Spend and network approvals

Spend needs a named switch on the command line. There is no config file way to approve it.

| Switch | Required by | Authorizes |
|---|---|---|
| `-ApprovePersistentCosts` | `Deploy` | Resources that bill while idle: Premium registry, storage, private endpoints, logging |
| `-ApproveGpuSpend` | `Start`, and `Deploy` with `compute_enabled=true` | A variable-cost Spot A100, at most one node |
| `-ApproveCustomerNsgRules` | `Start` or `Deploy` when `existing_gpu_nsg_id` is set | The operator's statement that the security team reviewed the NSG rules |

The last one is an acknowledgment. The script says so itself: it is "operator acknowledgment, not automatic rule verification".

The price check is a ceiling on the list price. The script prints that it "is not a Spot max-bid setting or billing cap; capacity is not guaranteed". But Spot prices vary, and the guard cannot cap them.

If any step after compute creation fails, the catch block runs `Stop-Demo` when the compute apply had started, and the lighter `Disable-LocalSubmissions` otherwise. It never leaves a half-armed studio behind.

### The cluster contract

`Assert-Cluster` is a single boolean over the live compute. A node that does not match fails Start and fails `Submit`:

```powershell title="scripts/Invoke-WanSafetyStudio.ps1"
$c.vmSize -eq $VmSize -and $c.vmPriority -eq 'LowPriority' -and $c.osType -eq 'Linux' -and
$c.scaleSettings.minNodeCount -eq 0 -and $c.scaleSettings.maxNodeCount -eq 1 -and
$c.scaleSettings.nodeIdleTimeBeforeScaleDown -in @('PT120S','PT2M') -and
$c.enableNodePublicIp -eq $false -and $c.remoteLoginPortPublicAccess -eq 'Disabled' -and
```

Read it as `min 0, max 1, 120 second idle, no public IP, Spot`, written as code.

## What the Python guard enforces per job

`azureml\cost_guard.py` is copied into the upstream package at Prepare time, and the cost patch makes both of the upstream job factories call it. `job_controls(args)` runs before any submission and raises on the first failure. The rules, in the order the code checks them:

1. The subscription, resource group and workspace equal the foundation's, and the Azure CLI account matches the selected tenant and subscription (`validate_scope`).
2. The profile matches `[a-z0-9_]+` and a `prepared-<profile>.json` exists for it.
3. The prepared scope fingerprint still matches the live selection.
4. `armed.json` exists and matches compute, profile and release version.
5. `timeout_seconds` is an integer from 1 to 7200. A boolean is refused.
6. The compute name matches the foundation and the source SHA equals the pinned `UPSTREAM_SHA`.
7. Workflow and profile match the prepared contract, and the environment id, models path and code path equal what Prepare recorded. A job cannot point at an unprepared environment.
8. The generated output path is under the private datastore's `video-library/` prefix with no query, fragment, `..`, backslash or `%`.
9. Dependencies are not installed at run time (`install_runtime_deps` is refused). They are baked on CPU in Prepare.
10. Batch size is exactly one video per job.
11. Input images are private datastore paths under `studio/web-inputs/`, never signed URLs.
12. The prepared compute identity equals the foundation's.

It returns the command limits (timeout), one instance, and the managed identity. Those go into the job as explicit controls, and the patch ends with `**controls` on the job factories, which `test_patch_covers_both_factories_and_disables_paid_model_downloads` checks.

### Read-back after submit

A guard that only checks the request trusts the request, so `verify_created_job` reads the persisted job back from Azure ML and checks that the server actually recorded the controls:

```python title="azureml/cost_guard.py"
def verify_server_controls(job, args):
    foundation = load_foundation()
    properties = job.get("properties", job) if isinstance(job, dict) else job
    timeout = normalize_timeout(server_field(server_field(properties, "limits"), "timeout"))
    requested_timeout = normalize_timeout(getattr(args, "timeout_seconds", MAX_SECONDS))
    if timeout > min(Decimal(MAX_SECONDS), requested_timeout):
        raise ValueError("Server timeout exceeds the approved/requested maximum.")
```

It also needs instance count exactly one and the job assigned to the studio compute. `normalize_timeout` understands seconds, `timedelta` and ARM ISO 8601 durations (`PT2H`, `P0DT1H30M`) and refuses anything it cannot parse instead of assuming a limit.

If the read-back fails for any reason, the job is canceled once, a status line `ServerSafetyVerificationFailed-CancellationRequested` is printed, and `ServerJobSafetyError` tells the operator to run Stop. There is no resubmit. Errors surface through `public_error`, which prints only the exception type and a fixed sentence, so an SDK error carrying a SAS token never reaches the log.

:::warning
When you change anything in this path, expect Prepare to be needed again, because `cost_guard.py` is part of the [release version](./overview.mdx#release-version). Run the [tests](./testing.mdx) first. They are written to fail closed: an unrecognized input must be rejected.
:::

## What Stop guarantees

`Stop` is built so that it can run with Python, Docker and the price API all unavailable. It runs these in order and reports every failure at the end rather than stopping at the first:

1. Write `release-required.json`.
2. Remove `armed.json`, stop the local server, set the hosted gate to `false`.
3. Cancel every active job in the workspace (cancellation errors are collected, not fatal).
4. Delete the compute with `underlyingResourceAction=Delete` and wait until it is absent.
5. Detach the NAT gateway from the GPU subnet, then delete the NAT gateway and its public IP. It refuses to detach a NAT that is not the studio's.
6. Wait until all jobs are terminal.
7. Reconcile Terraform state with `state rm` for exactly five addresses and a refresh-only apply. Each address is checked against the live resource id before removal.
8. Delete `release-required.json` and print `VERIFIED OFF`.

The marker file does the work. If Stop dies at step 4, `release-required.json` remains, and `Start` refuses to run until Stop completes. A half-finished release cannot be mistaken for a clean one.

Every script run prints a warning that Stop is not a zero bill: the registry, storage, models, videos, private endpoints and logging remain. Compute, NAT and the public IP are what Stop removes.
